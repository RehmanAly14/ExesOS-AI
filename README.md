# ExesOS AI — Backend API

**ExesOS AI** (also branded as **ExecOS AI**) is an AI-powered business operating system backend. It provides a REST API for workspace management, business profiles, document ingestion, RAG-powered chat, and executive report generation — all backed by a multi-agent AI pipeline powered by [Fireworks AI](https://fireworks.ai).

> **Frontend lives in a separate repository:** [ExesOS-Frontend](https://github.com/ExesOS/ExesOS-Frontend)  
> This repo contains **only the backend API server**. The React/Vite frontend consumes these endpoints and is developed and deployed independently.

## Features

| Module | Description |
|--------|-------------|
| **Authentication** | Register, login, JWT-based sessions, protected routes |
| **Workspaces** | Multi-tenant workspaces owned by users |
| **Businesses** | Business profiles with industry, stage, AI context, and preferences |
| **Documents** | Upload PDF, DOCX, or TXT files; automatic text extraction and embedding |
| **RAG Chat** | Context-aware chat using vector similarity search over uploaded documents |
| **Multi-Agent AI** | Keyword-routed specialist agents (Finance, Marketing, Sales, Operations, CEO) |
| **Executive Reports** | Full business health reports generated by the CEO agent workflow |

## Tech Stack

- **Runtime:** Node.js 20
- **Framework:** Express.js
- **Database:** PostgreSQL with Prisma ORM
- **AI Provider:** Fireworks AI (LLM + embeddings)
- **Auth:** JWT + bcrypt
- **File Parsing:** `pdf-parse`, `mammoth` (DOCX)
- **Validation:** express-validator, Zod
- **Security:** Helmet, CORS

## Getting Started

### Prerequisites

- Node.js 20+
- PostgreSQL 14+
- A [Fireworks AI](https://fireworks.ai) API key
- The [ExesOS-Frontend](https://github.com/ExesOS/ExesOS-Frontend) repo (for the UI)

### 1. Clone and install

```bash
git clone <this-repo-url>
cd "ExesOS AI/server"
npm install
```

### 2. Configure environment

```bash
cp .env.example .env
```

Edit `.env` with your values:

| Variable | Description |
|----------|-------------|
| `DATABASE_URL` | PostgreSQL connection string |
| `JWT_SECRET` | Secret key for signing tokens |
| `FIREWORKS_API_KEY` | Your Fireworks AI API key |
| `CLIENT_URL` | Frontend origin for CORS (default: `http://localhost:5173`) |

### 3. Set up the database

```bash
npx prisma generate
npx prisma migrate dev
```

### 4. Run the server

```bash
# Development (with hot reload)
npm run dev

# Production
npm start
```

The API will be available at `http://localhost:5000/api`.

### 5. Connect the frontend

Clone and run [ExesOS-Frontend](https://github.com/ExesOS/ExesOS-Frontend) separately. Point its API base URL to `http://localhost:5000/api` and ensure `CLIENT_URL` in this server's `.env` matches the frontend's origin.

## API Endpoints

All routes are prefixed with `/api`. Protected routes require a valid JWT (sent via cookie or `Authorization: Bearer <token>`).

### Health

| Method | Endpoint | Description |
|--------|----------|-------------|
| `GET` | `/api/health` | Server health check |

### Auth

| Method | Endpoint | Access | Description |
|--------|----------|--------|-------------|
| `POST` | `/api/auth/register` | Public | Register a new user |
| `POST` | `/api/auth/login` | Public | Login and receive JWT |
| `GET` | `/api/auth/me` | Private | Get current user |
| `POST` | `/api/auth/logout` | Private | Logout |

### Workspaces

| Method | Endpoint | Description |
|--------|----------|-------------|
| `POST` | `/api/workspaces` | Create workspace |
| `GET` | `/api/workspaces` | List my workspaces |
| `GET` | `/api/workspaces/:id` | Get workspace by ID |
| `DELETE` | `/api/workspaces/:id` | Delete workspace |

### Businesses

| Method | Endpoint | Description |
|--------|----------|-------------|
| `POST` | `/api/businesses` | Create business |
| `GET` | `/api/businesses/:workspaceId/businesses` | List businesses in workspace |
| `GET` | `/api/businesses/:id` | Get business by ID |
| `PATCH` | `/api/businesses/:id` | Update business profile |
| `DELETE` | `/api/businesses/:id` | Delete business |

### Documents

| Method | Endpoint | Description |
|--------|----------|-------------|
| `POST` | `/api/documents` | Upload document (multipart, field: `file`) |
| `GET` | `/api/documents/business/:businessId` | List business documents |
| `GET` | `/api/documents/:id` | Get document by ID |
| `PATCH` | `/api/documents/:id/embedding-status` | Update embedding status |
| `DELETE` | `/api/documents/:id` | Delete document |

Supported file types: **PDF**, **DOCX**, **TXT**.

### Chat

| Method | Endpoint | Description |
|--------|----------|-------------|
| `POST` | `/api/chat` | Send a message (RAG + agent routing) |
| `GET` | `/api/chat/history` | Get chat history for a business |

Chat automatically triggers an **executive report** when the message contains keywords like "executive report", "generate report", or "strategic review".

### Reports

| Method | Endpoint | Description |
|--------|----------|-------------|
| `POST` | `/api/reports` | Generate executive report |
| `GET` | `/api/reports` | List reports for a business |
| `GET` | `/api/reports/:id` | Get report by ID |
| `DELETE` | `/api/reports/:id` | Delete report |

## AI Pipeline

### Document Ingestion Flow

1. User uploads a document via the API
2. Text is extracted (PDF → `pdf-parse`, DOCX → `mammoth`, TXT → raw read)
3. `EmbeddingPipeline` chunks the text and generates embeddings via Fireworks
4. Chunks + embeddings are stored in PostgreSQL (`document_chunks` table)

### RAG Retrieval

When a chat message arrives:

1. The query is embedded using Fireworks
2. `PostgreSQLRetrievalService` loads scoped chunks and scores them with cosine similarity
3. Top-K relevant chunks are packaged as context for the agent

### Agent Routing

`AgentRouter` inspects the user's message and routes to a specialist:

| Agent | Trigger Keywords |
|-------|-----------------|
| **Finance** | revenue, profit, expense, budget, invoice, finance |
| **Marketing** | campaign, branding, advertisement, marketing, brand |
| **Sales** | sales, leads, pipeline, conversion, sell, customer |
| **Operations** | inventory, logistics, workflow, process, operations |
| **CEO** | Default fallback + executive report workflow |

Each specialist agent extends `BaseAgent` and returns structured markdown insights using Fireworks LLM with JSON schema validation.

### Executive Reports

The CEO workflow (`WorkflowOrchestrator`) gathers:

- Business profile and AI context
- Recent chat history
- Retrieved document context

It then makes a single structured LLM call to produce a full executive report with business health score, confidence, and markdown output — persisted in the `reports` table.

## Database Models

## Frontend Repository

The user-facing application is **not in this repo**. It lives at:

**[ExesOS-Frontend](https://github.com/ExesOS/ExesOS-Frontend)**

The frontend is a separate React/Vite application that:

- Handles user registration, login, and session management
- Provides the workspace and business management UI
- Offers document upload and chat interfaces
- Displays executive reports and business dashboards

To run the full stack locally:

1. Start this backend (`npm run dev` in `server/`)
2. Clone and start [ExesOS-Frontend](https://github.com/ExesOS/ExesOS-Frontend)
3. Ensure `CLIENT_URL` in `.env` matches the frontend dev server origin (typically `http://localhost:5173`)

```

JWT_SECRET=...

FIREWORKS_API_KEY=...
FIREWORKS_LLM_MODEL=accounts/fireworks/models/gpt-oss-120b
FIREWORKS_EXECUTIVE_MODEL=accounts/fireworks/models/gpt-oss-120b
FIREWORKS_EMBEDDING_MODEL=nomic-ai/nomic-embed-text-v1.5
RETRIEVAL_TOP_K=5
```

Fireworks models are validated against your account on startup. A fallback chain is used if the primary model is unavailable.
